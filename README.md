# ComfyUI-PhotoCraft

> [English] | [中文文档](README-zh.md)

Original bridge plugin: let PhotoCraft users run ComfyUI AI generation /
inpaint / redraw **without modifying PhotoCraft source**, and bring the
result back into PhotoCraft.

> PhotoCraft has no Photoshop-style UXP panel, no ExtendScript remote
> connection, and no plugin compatibility (its README says so). Its real
> extension points are: the JSON control channel, the headless
> `photocraft-cli`, WASM sandbox filter plugins (no network), and file
> formats (`.pcraft` / PSD / PSB / PNG …). This plugin therefore does
> **not** embed a panel inside PhotoCraft. It is: ComfyUI nodes + a Python
> bridge backend + a standalone local web side panel (open in a browser,
> next to PhotoCraft) + a PhotoCraft adapter (file mode + live control-
> channel mode).

All code in this repo is original. It only follows the *public
architectural idea* of the reference Photoshop bridge (panel + ComfyUI
nodes + WebSocket + local file exchange). No source from any existing
repository was copied.

## Prerequisites

| Requirement | Notes |
|---|---|
| PhotoCraft | Desktop app or `photocraft-cli`. Live mode needs `--control` (see below). |
| ComfyUI | A working local ComfyUI install with its usual models. |
| GPU | Local GPU recommended (≥ 6 GB VRAM suggested for SD1.5); CPU works but is slow. |
| Python | 3.10+. The plugin uses only the stdlib plus what ComfyUI already provides. |
| aiohttp | Required only to *serve* `py/backend.py` (ComfyUI normally already has it). |

No API key is needed. All models run locally.

## Install

```bash
# 1. Copy / link into ComfyUI (no admin, no git, no pip)
python3 install.py --comfyui-root /path/to/ComfyUI \
  --photocraft-cli photocraft-cli \
  --control-token-file /private/path/photocraft-control.token \
  --backend-token-file /private/path/pc-bridge.token \
  --automation-read-root /path/to/work \
  --automation-write-root /path/to/work \
  --mode file

# 2. Start the bridge backend (loopback only)
python3 -m py.backend --host 127.0.0.1 --port 8190

# 3. Open the side panel in a browser
#    photocraft_panel/index.html  (paste the bridge token in Settings)

# 4. Restart ComfyUI so the nodes load.
```

Uninstall:

```bash
python3 uninstall.py --comfyui-root /path/to/ComfyUI [--remove-config]
```

## Two modes

### File mode (default, `mode=file`)

1. Export a document to `data/pc_inputs/PC_canvas.png` (and a mask to
   `PC_mask.png`, plus `config.json` with prompts / seed / slider) — via
   the panel, or via the adapter:
   `adapter.export_canvas_mask("doc.psd")`.
2. Run a workflow in ComfyUI using `PhotoCraftToComfyUI` →
   `ComfyUIToPhotoCraft`.
3. Apply the staged render back with `adapter.import_result(...)` or the
   panel's **Apply back to PhotoCraft** button.

### Live mode (`mode=live`)

Start PhotoCraft yourself with its control channel (the plugin never
starts PhotoCraft for you):

```bash
photocraft --control 7878 \
  --control-token-file /private/path/photocraft-control.token \
  --automation-read-root /path/to/work \
  --automation-write-root /path/to/work
```

Then use the `PhotoCraftControl` node (`engine.execute`) or
`POST /pc/command` to run commands such as `layer.new.layer`,
`doc.info`, `ui.inspect`, `ui.screenshot`. Live mode is the only mode
that executes engine commands; file mode stages files.

## Configuration

`config.json` (generated by `install.py`; tokens are *file paths*, never
token values):

| Key | Meaning |
|---|---|
| `photocraft_cli` | Path / name of `photocraft-cli` |
| `control_host` / `control_port` | PhotoCraft control channel (must stay `127.0.0.1`) |
| `control_token_file` | Private file holding the PhotoCraft control token |
| `automation_read_root` / `automation_write_root` | Directories PhotoCraft may read / write |
| `comfyui_host` / `comfyui_port` | ComfyUI address (loopback) |
| `backend_host` / `backend_port` | This bridge backend (must stay `127.0.0.1`) |
| `backend_token_file` | Private file holding this bridge's token |
| `inputs_dir` / `outputs_dir` | `data/pc_inputs` / `data/pc_outputs` |
| `mode` | `file` or `live` |

## Nodes

| Node | Purpose |
|---|---|
| `PhotoCraftToComfyUI` | Reads `PC_canvas.png` / `PC_mask.png` / `config.json`; outputs `(IMAGE, MASK, FLOAT, INT, STRING, STRING, INT, INT, STRING, STRING)`. `IS_CHANGED` uses MD5 of the three files. |
| `ComfyUIToPhotoCraft` | SaveImage-style save + `GET /pc/renderdone?filename=…` notify + `last_render.json` sidecar. |
| `ClipPass` / `ModelPass` | Pass CLIP / MODEL through unchanged. |
| `PhotoCraftControl` | Runs a PhotoCraft `engine.execute` command over the control channel (live). No ExtendScript. |

## Workflows (`data/workflows/`)

| File | Use |
|---|---|
| `pc_sd15_txt2img.json` | SD1.5 text-to-image |
| `pc_sd15_inpaint.json` | SD1.5 inpaint (canvas + mask, denoise = slider) |
| `pc_sd15_controlnet.json` | SD1.5 ControlNet lineart (strength = slider) |
| `pc_sd15_upscale.json` | SD1.5 4× upscale |
| `pc_sdxl_txt2img.json` | SDXL text-to-image |

Each workflow references `PhotoCraftToComfyUI` / `ComfyUIToPhotoCraft`
and only standard ComfyUI node types
(`CheckpointLoaderSimple`, `CLIPTextEncode`, `KSampler`, `VAEDecode`,
`ControlNetLoader`, `UpscaleModelLoader`, …). Prompt placeholders for
`en-US / zh-CN / zh-TW / ja-JP / ko-KR` are in each file's `_meta`.
Replace `ckpt_name` / `control_net_name` / `model_name` with models you own.

## Security

Deliberate fixes for the flaws found in the reference Photoshop bridge:

* `/pc/*` binds only `127.0.0.1` and requires a Bearer token from a
  private token file. **No default password** (never `12341234`), no
  unauthenticated route.
* No `git reset --hard`, no automatic `pip install`, no installer that
  requests admin rights, no code execution from strings.
* Every file path is validated with `commonpath` checks; reads/writes stay
  inside the configured automation roots / inputs / outputs.
* Frontend uses `ws://` only for loopback, with a token attached.
* Clients are tracked in separate `pc_clients` / `cm_clients` dicts —
  never “last connected client” routing.
* The bundled `.ccx`-style opaque binary problem is avoided: there is no
  binary plugin package in this repo.

Keep the bridge on loopback. Do not put it behind a public reverse proxy
without adding TLS + your own authentication in front.
